00

Les outils

Avant de coder

Pour tout ce cours, il te faut trois choses : un éditeur de texte (VS Code est gratuit et le plus utilisé), un navigateur (Chrome, Firefox, Edge — peu importe, tant qu'il a un inspecteur), et un dossier de projet. Pas besoin d'installer Node.js, de framework, ni quoi que ce soit d'autre : tout ce cours tourne avec un simple navigateur.

Le navigateur a un inspecteur (touche F12, ou clic droit → « Inspecter ») qui contient un onglet Console (pour voir les messages et erreurs JavaScript) et un onglet Elements/Éléments (pour voir le HTML réel de la page). Tu vas t'en servir sans arrêt.

Exercice

Installe VS Code si tu ne l'as pas déjà. Crée un dossier vide quelque part sur ton ordinateur, appelé par exemple aganews-exercices, et ouvre-le dans l'éditeur. Ouvre ensuite l'inspecteur de ton navigateur sur n'importe quel site pour repérer où sont les onglets Console et Éléments.

01

Le Markdown

Écrire du texte enrichi sans balises

Le Markdown est une façon d'écrire du texte formaté (titres, gras, listes, liens…) avec de simples symboles au clavier, en restant lisible même non transformé. Il n'est pas compris nativement par le navigateur comme le HTML : ce n'est que du texte brut, qu'il faudra convertir plus tard (module 8).

Tu veuxHTMLMarkdown
Titre<h1>Bonjour</h1># Bonjour
Gras<strong>fort</strong>**fort**
Italique<em>doux</em>*doux*
Liste<ul><li>Item</li></ul>- Item
Lien<a href="...">clic</a>[clic](...)
Citation<blockquote>...</blockquote>> texte
Exercice

Crée un fichier essai.md. Écris un texte contenant : un titre principal, un sous-titre, une phrase avec un mot en gras et un en italique, une liste de 3 éléments, et un lien.

Indice

Un sous-titre utilise deux dièses : ## Sous-titre. Pense à laisser une ligne vide entre chaque bloc (titre, paragraphe, liste) — c'est cette ligne vide qui sépare les éléments en markdown.

02

HTML : la structure

Le squelette d'une page

HTML décrit la structure d'une page avec des balises qui s'ouvrent <tag> et se ferment </tag>. Toute page commence par le même squelette minimal :

<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="UTF-8">
  <title>Titre de l'onglet</title>
</head>
<body>
  <h1>Titre visible</h1>
  <p>Un paragraphe.</p>
</body>
</html>

Balises utiles à connaître : h1 à h6 (titres), p (paragraphe), a href="..." (lien), ul/li (liste), img src="..." alt="..." (image), div (bloc générique), et les balises « sémantiques » header, main, footer qui donnent du sens à une zone de la page.

Exercice

Crée test.html avec le squelette minimal. Ajoute dedans : un h1, un paragraphe de présentation, une liste de 3 choses que tu aimes, un lien. Ouvre le fichier en double-cliquant dessus : il doit s'ouvrir dans ton navigateur.

Indice

Page blanche ? Vérifie que le fichier a bien l'extension .html (pas .html.txt, une erreur fréquente avec certains éditeurs), et que chaque balise ouverte est bien refermée.

03

CSS : la mise en forme

Couleurs, espacements, agencement

CSS décrit l'apparence : couleurs, tailles, espacements, positionnement. On cible des éléments avec un sélecteur, puis on leur donne des propriétés.

body {
  font-family: sans-serif;
  background: #f0f0f0;
}
h1 {
  color: darkred;
}
.ma-classe {
  margin-bottom: 1rem;
}

Pour lier une feuille CSS à ta page, dans le <head> :

<link rel="stylesheet" href="style.css">

Vocabulaire clé : sélecteur (balise, .classe, #id), propriété/valeur, et le box model (de l'intérieur vers l'extérieur : contenu → padding → border → margin).

Exercice

Crée style.css à côté de test.html, lie-le. Donne une couleur de fond à la page, une couleur différente à ton h1, et du padding à ta liste. Bonus : mets 2-3 éléments dans un div et essaie display: flex; dessus pour les aligner côte à côte.

04

JavaScript de base

Variables, fonctions, tableaux, objets

JS rend la page interactive. On le lie juste avant </body> (pour que le HTML soit déjà chargé quand le script s'exécute) :

<script src="script.js"></script>

Les briques de base :

const nom = "Aga";
let age = 20;

function direBonjour(n) {
  return "Bonjour " + n;
}

const fruits = ["pomme", "poire", "kiwi"];
for (const f of fruits) {
  console.log(f);
}

const article = { titre: "Mon titre", date: "2026-09-16" };
console.log(article.titre);

const = variable qui ne change pas, let = variable qui peut changer. Un tableau ([]) contient une liste de valeurs. Un objet ({}) associe des clés à des valeurs, comme le frontmatter d'un article.

Exercice

Crée script.js, lie-le à ton HTML. Écris un tableau de 3 objets représentant des articles fictifs (chacun avec au moins titre et date). Fais une boucle qui affiche chaque titre avec console.log. Recharge la page, ouvre la console (F12) pour vérifier.

05

Le DOM

Modifier la page depuis le script

Le DOM (Document Object Model) est la représentation en mémoire de ta page, que JS peut lire et modifier. document.querySelector trouve un élément, .textContent change son texte, document.createElement + .appendChild en créent de nouveaux.

const titre = document.querySelector("h1");
titre.textContent = "Nouveau titre";

const liste = document.querySelector("ul");
const item = document.createElement("li");
item.textContent = "Nouvel élément";
liste.appendChild(item);
Exercice

Reprends ton tableau d'articles fictifs du module 4. Ajoute une <ul id="liste-articles"></ul> vide dans ton HTML. Au lieu d'un console.log, crée dynamiquement un <li> par article (avec son titre) et ajoute-le à cette liste.

Indice

Sélectionne la liste une seule fois, avant la boucle. À l'intérieur de la boucle, crée un nouvel élément à chaque tour et ajoute-le.

06

Fetch & async

Aller chercher un fichier externe

Jusqu'ici, tes données étaient écrites en dur dans le script. fetch() va chercher un fichier externe, mais ça prend du temps : c'est asynchrone. Les mots-clés async/await permettent d'écrire ce code presque comme du code normal.

async function chargerFichier() {
  const reponse = await fetch("mon-fichier.txt");
  const texte = await reponse.text();
  console.log(texte);
}
chargerFichier();
Piège classique : fetch() sur un fichier local ne marche pas si tu ouvres ton HTML en double-cliquant (protocole file://). Il faut un petit serveur local.

Deux façons simples de lancer un serveur local dans ton dossier de projet :

  • Avec Python : python3 -m http.server 8000, puis ouvrir http://localhost:8000
  • Avec VS Code : installer l'extension « Live Server », clic droit sur le HTML → « Open with Live Server »
Exercice

Crée salut.txt contenant une phrase. Écris une fonction async qui le charge avec fetch et affiche son contenu dans une balise de ta page (pas juste console.log, en réutilisant le module 5). Lance un serveur local pour tester.

07

Le Frontmatter

Les métadonnées en haut d'un article

Pour qu'un article ait un titre, une date, un auteur sans les deviner depuis le texte, on ajoute un bloc de métadonnées en haut du fichier, entre deux lignes ---. C'est une convention très répandue (Jekyll, Hugo, Next.js…).

---
title: Mon titre
date: 2026-09-20
---

Le contenu de l'article...

Il faut donc écrire une fonction qui : 1) sépare le texte en deux (le bloc de métadonnées et le reste), 2) transforme chaque ligne clé: valeur en objet JS.

Outils utiles (pas la solution, juste le nécessaire) : .split("\n") découpe un texte en lignes. .indexOf(":") trouve la position du premier :. .slice(debut, fin) découpe une chaîne. .trim() retire les espaces autour.

Exercice

Écris une fonction parseFrontmatter(texte) qui prend une chaîne comme ci-dessus et retourne { data: {title: "Mon titre", date: "2026-09-20"}, content: "Le contenu de l'article..." }. Teste-la avec 2-3 exemples écrits en dur dans ton script (pas besoin de fetch pour cet exercice, entraîne-toi sur la logique seule).

Indice

Repère la position de la première ligne --- et de la deuxième. Tout ce qui est entre les deux, c'est le frontmatter (à découper ligne par ligne). Tout ce qui vient après la deuxième, c'est le contenu.

08

Markdown → HTML

Convertir le texte en vraies balises

Le markdown n'est que du texte : pour que le navigateur affiche un vrai <h1> ou un vrai <strong>, il faut le transformer en HTML. Deux étapes pédagogiques, dans l'ordre :

1. Comprendre le principe : écris une fonction qui gère seulement 2-3 règles simples avec des expressions régulières (« regex ») et .replace().

texte.replace(/\*\*(.+?)\*\*/g, "<strong>$1</strong>")

Cette ligne remplace chaque **mot** par <strong>mot</strong>.

2. Utiliser une vraie librairie : pour un rendu complet et fiable (listes, code, citations, liens imbriqués...), on utilise une librairie déjà écrite plutôt que de tout réinventer. marked est l'une des plus utilisées. Télécharge son fichier marked.umd.js (disponible sur github.com/markedjs/marked, dossier lib/), place-le dans un dossier vendor/ de ton projet, puis :

<script src="vendor/marked.min.js"></script>
<script>
  const html = marked.parse("# Titre\n\nUn paragraphe en **gras**.");
  document.querySelector("#zone").innerHTML = html;
</script>
Exercice
  1. Écris markdownVersHtml(texte) qui remplace # titre par <h1>titre</h1> et **mot** par <strong>mot</strong> avec des regex.
  2. Ensuite, récupère marked, et utilise marked.parse() sur le content extrait par ta fonction parseFrontmatter du module 7.
09

Architecture du site

Organiser les fichiers du projet

Tu as maintenant tous les outils : HTML/CSS/JS, DOM, fetch, frontmatter, markdown→HTML. Il faut organiser le projet. Rappel de l'idée : chaque article = un fichier .md dans un dossier articles/. Comme JS ne peut pas lister automatiquement le contenu d'un dossier depuis le navigateur (restriction de sécurité), il faut une liste manuelle : un fichier manifest.json qui contient les noms des fichiers à afficher.

mon-site/ index.html page d'accueil article.html page d'un article css/style.css js/ (tes scripts) vendor/marked.min.js articles/ manifest.json liste des fichiers .md premier-article.md deuxieme-article.md
Exercice

Crée cette arborescence de dossiers/fichiers (vides pour l'instant, tu les rempliras dans les modules suivants). Écris 2 vrais articles .md avec le frontmatter du module 7. Écris manifest.json : un tableau JSON avec les 2 noms de fichiers, par exemple ["premier-article.md", "deuxieme-article.md"].

10

La page d'accueil

Assembler fetch + DOM + tri

C'est ici que tout se connecte. Les étapes logiques, à coder toi-même dans cet ordre :

  1. fetch("articles/manifest.json") puis .json() pour obtenir la liste des noms de fichiers.
  2. Pour chaque nom, fetch("articles/" + nom) puis .text() pour le contenu brut.
  3. parseFrontmatter() (module 7) pour extraire titre / date / extrait.
  4. Trier le tableau résultant par date, du plus récent au plus ancien.
  5. Pour chaque article, créer un élément DOM (module 5) affichant titre + date + extrait, avec un lien vers article.html?slug=....

Pour attendre plusieurs fetch en parallèle avant de continuer, combine .map() et Promise.all() :

const resultats = await Promise.all(
  tableau.map(async (item) => {
    const r = await fetch(item);
    return await r.text();
  })
);

Pour trier par date décroissante, une comparaison classique :

tableau.sort((a, b) => new Date(b.date) - new Date(a.date));
Exercice

Implémente index.html + le script qui charge le manifest, charge chaque article, extrait ses métadonnées, trie par date, et affiche une liste de cartes cliquables. Mets un ?slug=nom-du-fichier-sans-extension dans chaque lien.

Indice

Teste étape par étape : d'abord affiche juste les noms de fichiers (étape 1 seule), vérifie que ça marche, puis ajoute le contenu (étapes 2-3), puis le tri, puis le style. N'écris jamais tout d'un coup sans tester entre chaque étape — c'est la meilleure façon de localiser un bug.

11

La page d'article

Lire l'URL, afficher un article complet

Dans article.html?slug=mon-article, la partie après le ? est une « query string ». URLSearchParams permet de la lire :

const params = new URLSearchParams(window.location.search);
const slug = params.get("slug");
Exercice

Dans article.html, récupère le slug, fais fetch("articles/" + slug + ".md"), parse le frontmatter, affiche titre/date/auteur, et affiche le contenu converti en HTML avec marked.parse() (module 8) dans une zone dédiée.

Indice

Gère les cas d'erreur proprement : si slug est absent, affiche un message clair plutôt qu'une page blanche. Après le fetch, vérifie response.ok avant de continuer — un fichier introuvable ne lève pas d'erreur automatiquement avec fetch.

12

Ajouter, modifier, supprimer

Le workflow au quotidien

Pas de base de données ni d'interface d'admin : gérer le contenu, c'est manipuler des fichiers.

ActionCe que tu fais
AjouterNouveau fichier .md (frontmatter + contenu) + ajouter son nom dans manifest.json
ModifierÉditer directement le fichier .md concerné
SupprimerSupprimer le fichier + retirer son nom de manifest.json
Exercice

Fais le test complet : ajoute un 3ᵉ article, vérifie qu'il apparaît sur la page d'accueil à la bonne position selon sa date, clique dessus, vérifie l'affichage. Puis supprime-le et vérifie qu'il disparaît bien de la liste.

Pour publier en ligne (optionnel) : git add, git commit, git push, puis héberger gratuitement avec GitHub Pages (Settings → Pages → choisir la branche du dépôt).
13

Pour aller plus loin

Idées d'extensions, sans solution

Une fois les 13 chantiers précédents terminés, ton site fonctionne entièrement. Voici des pistes pour continuer à pratiquer seul, du plus simple au plus ambitieux :

  • Un champ image dans le frontmatter, affiché en haut de chaque carte d'article.
  • Des catégories ou tags, avec un filtre sur la page d'accueil.
  • Une barre de recherche qui filtre les articles par titre en direct.
  • Un mode sombre : un bouton qui bascule un thème, mémorisé avec localStorage.
  • De la pagination si tu accumules beaucoup d'articles.
  • Remplacer le manifest.json géré à la main par un petit script qui scanne automatiquement le dossier articles/ — attention, ça demande un mini serveur/build, ce n'est plus « juste un navigateur ».
Défi

Choisis une seule idée ci-dessus et implémente-la de bout en bout, sans indice cette fois.
